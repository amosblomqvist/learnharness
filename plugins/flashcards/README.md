# Flashcards

A self-contained native LearnHarness plugin: generate fact-recall cues from your graph or uploaded PDF/text files, organize them in flat decks, and review them with FSRS-6. **No Anki integration.** No runtime npm dependencies, private app imports, core graph writes or provider credentials in the package.

## Build and test

From this folder:

```sh
npm ci
npm test
npm run build
```

The build writes directly to this project's **`dist/`**. For distribution, copy its **contents** into `<learning data>/plugins/flashcards/dist/`, so the host finds `flashcards/dist/manifest.json`; never distribute persistent data. Or keep the source project at `<learning data>/plugins/flashcards/` and edit/build in that same workspace—no second install folder or development registration. Build cleanup only replaces `dist/`, refuses symlinked `dist/` or misplaced `dist/data/`, and leaves sibling **`flashcards/data/`** untouched. Refresh Settings → Plugins after installation or the first build, then enable Flashcards; restart LearnHarness after changing already loaded code. A root-only manifest is not loaded. This repository does not automatically install or enable it. Requires the app build exposing `mountKnowledgePicker`, `mountMarkdown`, `mountTree`, page-body `openSurface`, public `mountButton` icons (`icon` / `iconOnly`) and custom colors (`variant: 'custom'` / `colors`), the surface `data-plugin-initial-focus` contract, and `ctx.workers` (the version string alone does not establish those capabilities). File generation additionally requires `ctx.documents.toMarkdown`; on an older host, only Generate from file is disabled, while graph generation and existing reviews remain available.

## Use

Open Flashcards from its stacked-card icon in the sidebar. Select propositions in the real host knowledge picker, run preflight, then confirm generation. It uses the current cheap model slot unless you set a plugin-specific override; calls can incur cost. Graph selection is manual; there are no automatic generation triggers. Each successful chunk adds useful missing cues without replacing existing cards or resetting schedules. Navigation does not cancel work. Failed/interrupted targets require an explicit new generation attempt.

First-generation cards join a deck named after their original source. Initial names use public chat titles or notes-file basenames; host imported-source rename overrides are not yet exposed by the learning reader. Rename collections locally, create custom decks and change memberships without changing core sources. One proposition can occur in multiple decks while keeping one collection, schedule and history. Keep at least one membership. To delete its sole deck, choose another destination; deletion never removes cards or progress.

### Write cards by hand

The **+** immediately left of a deck's gear opens **Create card**: enter a Name followed by Question and Answer using the same Markdown fields as Edit cue. Saving creates a new Flashcards-only target and its first cue together in that deck. There is no separate target-creation step or existing-target dropdown. Each deliberate new save creates a new target rather than matching existing names; retrying a lost response does not create duplicates.

The **+** on an active target row opens **Add cue**, with only Question and Answer. The new cue shares that target's existing schedule and memberships without resetting its history, learning cue or daily introduction count. All fields must be nonblank; Cancel creates nothing. Manual creation needs no configured model, makes no model calls and never writes to the graph. Handwritten targets remain active independently of graph contents, including after restart. Cue rows and the Archive have no creation controls.

### Library and review

The library uses the native Deck → Proposition → Cue tree, with search and Create deck grouped inside its bordered panel. Click a deck name to rename it inline (Enter/blur saves; Escape cancels); its adjacent outlined Review button starts deck review. Stacked-card glyphs mark decks and the Archive branch. Muted gear menus retain deck settings, memberships, editing/deletion and ordering. Click a cue for a rich question/answer preview, with the proposition name as its single dialog heading and the same centered question/divider/answer styling as review. The preview's red Delete button opens the existing deletion confirmation. Search disables ordering until cleared.

Branch selection includes descendants, mixed checkboxes show partial selection, and shared cues stay selected across decks. The action row is always visible: Review all / Practice all switch to Review selected / Practice selected when anything is selected, with natural button widths and a consistent gap as the labels expand. The selection count and Clear sit together on the right; Clear is disabled without a selection. A selection without active cues disables the selected actions rather than falling back to the whole library. Selected review uses exactly the selected active cues, not all cues of their propositions. If a learning/relearning proposition's pinned cue is excluded, that proposition waits for a review scope containing that cue.

Review opens on the host's dimmed, blurred main-pane surface, leaving the sidebar and top bar available. The centered card contains only the question and revealed answer; the controls and dimmed shortcut hints sit outside it. Review, practice and preview cards have a landscape 16:9 minimum height based on their width, with short content centered vertically. A short revealed answer stays within that minimum-sized box; longer content expands it naturally rather than overflowing a fixed aspect ratio. No generic heading appears on the question side; the proposition name appears only after reveal. Close using the host X or Escape. The host focuses the visible card region through the public initial-focus marker. Space only reveals: after reveal it never submits a scheduled-review rating, including on focused rating buttons. Use 1–4 when focus is not in a control, click a rating, or press Enter on a focused rating button. Rating buttons use red/amber/green/blue tints for Again/Hard/Good/Easy through the shared custom-color API. Reveal is a quieter outlined button with a short “Space” hint. The ready count hugs the card's bottom edge, aligned right above the controls. Think, reveal, then self-rate Again/Hard/Good/Easy. Review is local and makes no model calls. The “N ready” count includes the current proposition, due propositions and new propositions admissible under the daily limits; future learning steps are not counted until ready. It counts shared propositions, not every cue.

Ready learning/relearning comes first, then due reviews, then new propositions. New allowance defaults to 20 per deck/day; due reviews are uncapped. A first rating counts in every containing deck; only the admitting/studied deck controls admission. Whole-library review finds an eligible deck without creating a separate global allowance.

### Generate from a file

Choose **Generate from file…** and select one PDF or UTF-8 text file. The shared host converter uses the same PDF-to-Markdown engine as notes import and the PDF-reader tools; there is no second converter in this package. PDFs are identified by their header or `.pdf` filename, so a corrupt PDF is not silently treated as ordinary text. Other filenames are allowed when their content is valid UTF-8 text, rather than restricting uploads to a short extension list. Unsupported binary/invalid text, empty documents, and PDFs without extractable text are refused. There is no OCR; mixed PDFs may omit image-only pages and present notices before generation.

The confirmation shows the filename, conversion notices, estimated input tokens and the model-call cost warning. No model calls start until you confirm. Each confirmed new file creates one deck named with its filename, including extension, which you can rename normally. The agent creates atomic facts and recall cues **only inside Flashcards**: nothing is imported into the graph. Cues for one fact share its schedule, just like graph-backed cards; file facts remain active independently of graph contents. Review, practice, daily limits, memberships, editing and statistics work the same way for both origins.

Uploading the same filename and exact converted content reopens the existing file deck without another generation run; changed content creates a new deck without modifying existing cards or progress. Generation is chunked to the configured input budget and uses the current cheap slot or plugin override. Accepted work continues after navigation and uses the existing cancellation/recovery mechanisms. Explicit retries process failed/cancelled/interrupted chunks, never successful ones. A confirmed file keeps its deck even if generation fails or returns no cards, with a visible result/retry state.

Conversion limits are 25 MiB per file, 26 MiB actual multipart body, 1,000 PDF pages and 2 MiB final UTF-8 Markdown including page markers; excess is refused, never silently truncated. The host allows one conversion at a time and reports busy instead of queuing. Cancellation is best-effort: input/page/output limits are **not** a hard CPU timeout or peak-memory bound, and an aborted conversion may hold the slot until the underlying parser stops. Before generation confirmation, leaving the view aborts conversion or ignores late preparation results.

Only the converted Markdown is retained under plugin data for retry and repeat-file identification, not the original upload. Normal background-task records also retain their generation inputs. Uploads do not create graph sources or trigger the graph extraction pipeline.

### Spaced-repetition overview

Below the deck panel, the library-wide dashboard shows new/learning/review/relearning proposition counts, current due dates (overdue, today and the next seven study days), and fourteen study days of scheduled-review activity. Shared propositions count once; archived propositions and groups without active cues are excluded from the current-state and due charts. The due chart shows existing next due dates, not a prediction of future repetitions. Activity counts recorded ratings, including historical reviews of cards later archived or deleted, rather than unique propositions. Search and selection do not filter the overview. The overview shares the rating palette: New blue, Learning amber, Review green, Relearning red. Due bars use red for overdue, amber for today and blue for future days; activity bars are green. Only the due chart's second-line dates are dimmed, leaving weekdays and activity dates unchanged.

### Extra practice

Choose **Practice anytime** from a deck's gear menu, or **Practice selected / Practice all** in the selection row. Practice snapshots active cues in saved deck/proposition/cue order, deduplicating shared cues and excluding archived/deleted cards. It includes new and non-due cards without a daily limit. Reveal each answer, then select Next; Space reveals or advances. There are no ratings, schedule changes, introduction charges or history writes. Each cue appears once in that practice session. The practice counter counts other cues still in the snapshot, excluding the displayed cue. The counter hugs the card's bottom edge above the controls. “Practice mode does not change your review schedule.” sits centered near the bottom of the pane, flowing below long content instead of covering it. Reveal and Next are quiet outlined buttons with short “Space” hints. Close with the host X or Escape.

Settings control desired retention (initially 90%), learning steps (1m 10m), relearning steps (10m), local study-day start (04:00), input chunk budget (approximately 4,000 tokens), and generation model/thinking overrides. The model section has its own Follow cheap slot toggle: on follows both model and thinking and hides the override rows; off pins the current cheap model/thinking when available, or opens an unsaved model-selection draft if no cheap model is available. The Model setting uses the native sans label and standard “Follow cheap slot” description underneath it, with the toggle on the right. When off, only the model and thinking pickers appear side by side below, aligned right, without extra labels or a separate default-thinking/reset button. This uses the existing settings API without custom fonts, private widget styling, or extra API fields. Turning the toggle back on clears both overrides; no extra setting or schedule change is introduced. FSRS-6 uses published parameters and deterministic intervals (no fuzz or optimizer). Learning repetitions use the same cue; normal review weights cue selection by its latest self-rating. The schedule is proposition-level, intentionally not identical to card-level Anki scheduling.

Questions/answers use the host's real Markdown rendering, including code, tables, math and Mermaid. Edit cards without resetting progress. Deleting a cue removes it from future review and keeps a tombstone/history; generation sees it as an example not to restore. If its graph proposition disappears, its collection is archived and excluded from review; the same ID returning makes it active again. Source deletion does not reorganize surviving cards.

## Data and lifecycle

Plugin-owned state is `data/flashcards.json`: a versioned JSON snapshot, atomically replaced after local mutations. It contains decks, cues, schedules, review records, generation progress and lightweight file-source metadata. Handwritten targets use a local origin; cue creation receipts make manual-save retries idempotent even after restart, subsequent editing or deletion. Converted file text is stored separately under `data/sources/`, keeping large documents out of the snapshot rewritten on each review. Existing graph-backed records remain compatible and retain their schedules and history. Host-owned task records remain under `data/tasks/`; the plugin does not overwrite them. Disable/update preserves data. A corrupt/unsupported store is an error, never silently reset.

Review content mounts own only their DOM, widgets and timers. Host presentation cleanup/remount (including development StrictMode replay) does not close the logical review session; actual close, reopen and owner abort still tear down its content scopes. Accepted review ratings and worker chunks are applied once. Cancel closes the batch's application gate before cancelling outstanding tasks; previously applied chunks remain. Restart reconciles durable worker outcomes without replaying unfinished model work. A failed save is visibly separate from successful model generation; retry saving does not make another model call. Deck deletion waits until generation finishes or is cancelled to avoid stale destinations.

The initial store is deliberately small and simple: one backend process owns writes. Simultaneously running independent app-server processes against the same plugin data directory is not supported. If dataset size makes rewriting the snapshot expensive, measure that concrete case before introducing more storage machinery.

## Verification

The focused test suite covers storage, manual target/cue creation with durable save retries, generation, cancellation/recovery, cue-filtered review, shared-cap admission counts, memberships, scheduler fixtures, state/due/activity aggregates across DST, the dashboard, once-through read-only practice, tree selection/rename and frontend lifecycle. The initial package's isolated host proof covered actual knowledge selection → loopback worker → accepted cards → review → navigation and disable/re-enable persistence. File generation adds pure validation/chunking tests, backend tests with mocked durable workers, and frontend tests with a mocked document-conversion capability, including concurrent duplicate uploads, confirmation gating, cancellation/recovery, and failed-range retries. The new upload flow has not yet been browser-tested end to end with the actual host conversion endpoint or a real model provider.

The UI pass also has a reproducible actual-host browser proof (`npm run test:native`, with `LH_STANDALONE` and `LH_APPROVED_HOST_DIGEST` pointing to an approved frozen host). It copies that host and the exact built package into a disposable profile, uses Electron's Node plus headless Chrome, and tests native tree columns/selection, shared cues, focused rename preservation during notifications, failed drafts, rich preview, centered dimmed review, marked-region focus/shortcuts, colored rating styles, Settings layering, shared scheduling, close/navigation and narrow-view scrolling. It checks unchanged source/package bytes, graph/settings, zero external requests, and catalog-only loopback traffic. No real provider/account or learner data is used. The latest layout run completed all six UI assertion groups, but failed its final strict network gate on one aborted navigation request; it is not a clean native-test pass, and no exception was added. That run preceded the public button-icon change, dashboard/extra-practice additions, initial-focus marker and custom-color buttons; the latest behavior still requires verification on the updated host. Minimum card sizing has also been checked in an isolated browser fixture with mocked widgets at wide and narrow sizes: short answers preserve the card height, long answers expand without clipping, and practice/preview share the same minimum shape. This is not a full-host UI pass. Real-model cue quality and a native Electron-window/manual UX trial remain unverified.
