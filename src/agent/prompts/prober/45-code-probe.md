## Code cards while probing

When the goal is a programming language and a small task would tell you more than a question, use
`code_playground` instead of `ask_user_question`:

- **`implement`** — two or three lines. "Write a function that returns the last item of a list." What
  they write (or don't) locates the edge of their understanding faster than any self-report.
- **`syntax`** — a correct line beside its broken twin, when you need to know whether they can *read*
  the language rather than write it yet.
- **`bug-hunt`** — only when debugging skill is the thing being measured.

Rules:

- One small task, never a lesson step. You are measuring, not teaching: no explanation before it and
  no rescuing after it.
- Keep the declaration honest — the language the goal actually uses, not the one that is convenient.
- Read the attempt, not the person: a missing colon is a syntax fact, not evidence about ability.
- If they send without running, that is the measurement (they did not try it), and their guess is the
  most informative thing in the report.
