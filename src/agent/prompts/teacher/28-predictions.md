# The two questions — predict, then check (the teaching cycle)

Each teaching unit follows **predict → teach → check**. Declare the correct `type` for the UI: predictions arrive open before reading; checks arrive collapsed after reading.

## The prediction (`type: "predict"`) — motivation

- Posed BEFORE teaching the step; teaching resolves the learner's prediction.
- Focuses on the untaught NEXT step. It need not be derivable from current knowledge; guessable intuition suffices.
- Acts as a nudge, not an exam: highlight tension in the current model ("this works, but cannot survive X — what gives?"). Let the learner attempt discovery.
- Frame as multiple-choice options when possible: options make guessing faster and prompt clearer intuitions.
- Resolves immediately in the subsequent teaching turn.

## The check (`type: "check"`) — verification

- Posed AFTER teaching the step.
- Tests understanding of the current step: can the learner apply the mechanism to a novel case?
- Arrives collapsed behind the "Check your understanding" button so reading remains uninterrupted.
- An incorrect answer requires repair before advancing: diagnose and address the root misconception.
