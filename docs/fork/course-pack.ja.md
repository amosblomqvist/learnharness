# コースパック

この文書は、LearnHarness を個人用にフォークした版のための説明です。元のライセンスと著作者表示は変えていません。詳細は [NOTICE](../../NOTICE) にあります。

コースは、番号付きの章フォルダの集まりです。フォルダ名は `01. Boxes` のように数字で始まり、中に `Readme.md` があります。その隣にある画像（`png`、`jpg`、`gif`、`webp`、`svg`）も一緒に取り込まれます。それ以外のファイルは無視します。最初のプリセットは [system-design-notes](https://github.com/liquidslr/system-design-notes) です。プリセットは場所を指しているだけで、ノート本文は含みません。

日本語の校正に nanaism / yomiyasu は使っていません。この環境には入っていませんでした。

## Windows で取り込む

普段の勉強は開発サーバーで足ります。デスクトップ版のインストーラは別手順で、勉強を始めるために必須ではありません。

1. Node.js 22 以降を入れます。上流の CI は Node 26 です。
2. このリポジトリで、次を実行します。

```bat
npm ci
npm run dev
```

3. ブラウザで `http://localhost:3000/courses` を開きます。

ノートは、このリポジトリの外にクローンしてください。LearnHarness のツリーへコピーしたり、コミットしたりしないでください。

```bat
git clone https://github.com/liquidslr/system-design-notes.git %USERPROFILE%\src\system-design-notes
```

コース画面の入力欄に、フルパスを貼ります。例: `C:\Users\you\src\system-design-notes`。そのあと **Import local folder** を押します。

**Download from GitHub** は、その場で `https://codeload.github.com/liquidslr/system-design-notes/tar.gz/refs/heads/main` を取得し、一時ディレクトリに展開してからアーカイブを消します。自分で `git pull` して更新を見たいときは、ローカルのクローンを指定する方が素直です。

取り込んだ章は、アプリのデータディレクトリへコピーされます。

- `npm run dev` のとき: `<このリポジトリ>\data\courses\`（git の管理外）
- パッケージした Electron のとき: `LH_DATA_DIR` は `<userData>\data` です。Windows では、このアプリの userData は通常 `%APPDATA%\LearnHarness` なので、コピー先は `%APPDATA%\LearnHarness\data\courses\` になります。

コースカードの **Check for updates** で、同じ取り込みをやり直せます。中身が変わっていない章はコピーし直さず、モデルにも送りません。変わった章だけファイルを置き換えます。復習カードと、これまでに開いたセッションの記録は残します。フォルダから消えた章は「削除された」と表示します。カードは消さず、今日のキューからは外します。

**Also extract propositions into the knowledge graph** にチェックを入れると、変わった章ごとに、既存のノート取り込み（知識グラフへの抽出）を走らせます。モデルを設定するまではオフのままにしてください。章の数だけモデルを呼ぶので、全部を一度に抽出すると時間がかかります。モデルが未設定でも、章ファイルの取り込み自体は終わり、失敗の理由が章に残ります。モデルを設定したあと、チェックを入れた状態で **Check for updates** を押すと、まだ抽出ハッシュが一致していない章だけ再試行します。

設定の File access を制限している場合は、コースデータのフォルダ（またはクローン先）を許可フォルダに加えてください。許可がないと、教師はメッセージに書かれたパスを読めません。

## 学習と練習

**Study** は、通常の授業セッションを作ります。最初のメッセージには、コピーした `Readme.md` と章ディレクトリのパスが入ります。流れはこれまでどおり、測定、計画、授業です。そのメッセージを送るには、他のセッションと同じく Strong モデルの設定が必要です。モデルが無いときは、下書きが入力欄に残り、セットアップが開きます。

**Practice** は、同じファイルを材料にした練習セッションです。system-design のプリセットでは、面接形式の問題を一つ出し、章の枠に沿って進めるよう頼んでいます。順番は、要件、見積もり、ハイレベル設計、深掘り、まとめです。ほかのコースでは、この枠は付けず、章の内容を思い出させるオープンな問題になります。見出しの **Practice** は、その見出しに絞った練習です。

練習の結果はセッションの中に残ります。復習カードへは書き戻しません。上流の実装では、練習の結果はセッションの記録であって、習熟度ではありません。このフォークもそこは変えていません。

## 復習の間隔

間隔の計算は SM-2 です。Wozniak（1990）の短い公開式で、学習済みの重みを持ちません。手元だけで動き、テストで結果を固定できます。FSRS は既定の重みが必要で、このアプリがそれを同梱する理由がありません。

章ごとにカードが一つあります。`##` の見出しは、最大 12 個まで、それぞれ別のカードです。ボタンと SM-2 のグレードの対応は、Again が 1、Hard が 3、Good が 4、Easy が 5 です。

- グレードが 3 未満なら、繰り返し回数を 0 に戻し、間隔を 1 日にします。
- それ以外では、最初の間隔は 1 日、次は 6 日、その後は「直前の間隔 × 易しさ」を丸めた日数です。
- 易しさの初期値は 2.5 です。更新量は `0.1 - (5 - grade) * (0.08 + (5 - grade) * 0.02)` で、下限は 1.3 です。間隔の計算には、今回の更新前の易しさを使います。

カードの期限は、記録されている UTC の日付です。**Today's review** には、期限が来ている章と見出しが出ます。上流から消した章と、再取り込みで消えた見出し（retired）はファイルには残しますが、キューには出しません。

章の状態は次のとおりです。

| 状態 | 意味 |
| --- | --- |
| Not started | ひも付いたセッションも、復習カードも無い |
| Learning | 授業か練習のセッションがある、またはカードがある。ただし期限が来ているものは除く |
| Review due | 章カードか、現役の見出しカードの期限が来ている。マスターよりこちらを優先する |
| Mastered | 章カードの間隔が 21 日以上、繰り返しが 3 回以上、最後のグレードが 4（Good）以上で、今日は期限でない。すでに採点した見出しも同じ条件を満たす。まだ採点していない見出しは、マスターを妨げない |

知識グラフは、理解の度合いを保存しません。**In the knowledge graph** は、その章のノートから命題が取り込まれている、という印です。これだけでは状態は変わりません。

日付は UTC です。日本時間の夜遅くに復習すると、UTC ではすでに翌日になっていることがあります。

## 上流との同期

公開リポジトリは、取得専用の remote として残します。そこへ push したり、このフォークから上流へ pull request を出したりしないでください。

```bat
git remote add upstream https://github.com/amosblomqvist/learnharness.git
git fetch upstream
git merge upstream/main
```

push 先を塞いでおくなら、次も使えます。

```bat
git remote set-url --push upstream DISABLE_PUSH_DO_NOT_PUBLISH
```

衝突したときは、このフォークが足していないファイルは上流を採用し、コースパックのファイルは残します。対象は [NOTICE](../../NOTICE) に列挙してあります。重なりやすいのは `README.md`、`docs/README.md`、`docs/architecture.md`、`components/sidebar.tsx` です。

## デスクトップ版のビルド

上流の `npm run desktop:dist` は、署名付き macOS 用です。Windows 用ではありません。上流の手順では、Windows 上で [デスクトップのビルドとリリース](../desktop-release.md) の共通準備をしたあと、次を実行します。

```bat
npx electron-builder --win --x64 --publish never
```

このフォークの開発環境では、そのコマンドは実行していません。
