# Android APK Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. The user requested immediate implementation of the selected local APK and ChatGPT Pro approach.

**Goal:** Deliver an installable LearnHarness APK with local storage and ChatGPT Pro sign-in.

**Architecture:** Package the existing standalone Next server and a pinned Node Mobile runtime inside a native Android shell. Preserve the current teacher and storage; use the existing web subscription owner for OAuth in the system browser.

**Tech Stack:** Java, Android WebView, JNI/C++, Node Mobile 24, existing Next/React app.

**Spec:** `docs/superpowers/specs/2026-11-01-android-design.md`

## Global Constraints

- Same `cursor-provider` branch requested by the user; no production credentials in artifacts.
- Android 8+, loopback only, private data survives bundle replacement.
- User signs into ChatGPT; no embedded API key or developer account.

## Review Focus

- Other apps/websites reaching loopback APIs: deny requests without the capability.
- OAuth leaving the WebView: system-browser login and callback must preserve state.
- Process death/rotation/update: retain learning data and avoid a second Node instance.
- Desktop native binaries accidentally packaged: audit payload and run actual Android.
- File selection, offline startup and narrow screens: exercise on the emulator.

### Task 1: Android request boundary and payload

Files: `src/server/android-access.ts`, `proxy.ts`, `tests/android-access.test.ts`,
`scripts/android/*`, `android/runtime/*`.

- [ ] Write failing tests for capability validation and cross-site requests.
- [ ] Implement the Android boundary without changing desktop/web behavior.
- [ ] Package a curated standalone payload, reject secrets and replace native binaries.
- [ ] Verify boundary tests and payload startup on host Node.

### Task 2: Android host

Files: `android/app/*`, `android/*.gradle`, Gradle wrapper, `android/README.md`.

- [ ] Implement private bundle extraction, versioned atomic updates and one runtime.
- [ ] Implement JNI startup, lifecycle notification, startup health polling, browser
  authentication, WebView navigation/file chooser and keyboard/system-bar handling.
- [ ] Compile APK and check its manifest, native ABIs and signature.

### Task 3: Tablet integration

Files: tablet-specific shell/styles as required, documentation and build scripts.

- [ ] Exercise startup, local sessions, imports and OAuth browser launch on emulator.
- [ ] Fix observed compatibility failures; test their externally visible behavior.
- [ ] Verify persistence after app restart and offline startup.

### Task 4: Delivery

- [ ] Run repository tests, typecheck, lint, production build and Android checks.
- [ ] Independent review, address material findings, document remaining limits.
- [ ] Commit source on the requested branch and provide APK plus checksum.
