# Interface language and translations

LearnHarness ships its interface in English and Simplified Chinese. The language is a normal setting (Settings → General → Language); there is no URL routing and no per-page switch. It changes the UI chrome immediately and composes a language directive into the agents' system prompts, so a Chinese session is also taught in Chinese.

## How the strings work

UI copy is written in English **in the component** and passed through a hook:

```tsx
const t = useT();
return <button aria-label={t("Close settings")}>{t("Close settings")}</button>;
```

- The **English source string is the dictionary key**. There is no separate key namespace to invent, and a missing entry falls back to English, so a translation that lags behind the source never breaks a screen.
- Placeholders are written `{name}` in both the source and the translation and are filled by `t("Version {version}", { version })`.
- Components mounted without `I18nProvider` render English. That is why the existing render tests did not need a translator.
- The dictionaries live in `src/core/i18n/zh-CN/`, one module per surface (`sidebar`, `chat`, `question`, `graph`, `settings`, `dialogs`, `artifacts`, `plugins`, plus the shared `common`). `src/core/i18n.ts` owns the language registry, resolution, interpolation and the `translate()` seam.

## Adding a language

1. **Register it** in `APP_LANGUAGES` (`src/core/i18n.ts`): an `id` (BCP 47, e.g. `ja`), the language's own `label`, and `htmlLang`. The settings sanitizer, the `<html lang>` attribute and the picker all read this list.
2. **Create the surface modules** under `src/core/i18n/<id>/` with the same file names, export the same shape (`Readonly<Record<string, string>>`), and merge them in that directory's `index.ts`. Wire the merged map into `DICTIONARIES`.
3. **Translate** every key. Start from the failure output of `npm test -- tests/i18n.test.ts`: it names each literal the shell renders that has no entry.
4. **Add the directive** in `src/agent/prompt-language.ts` so the agents teach in that language, and reference the language in `languageDirective`.
5. **Run** `npm run typecheck`, `npm run lint` and `npm test`.

## Rules the tests enforce

`tests/i18n.test.ts` fails when:

- a literal rendered through `t("…")` has no translation;
- a translation is empty;
- a translation drops or renames a `{placeholder}`;
- one English string is owned by two surface modules (two translations for one source is always a mistake — move the shared string to `common`).

`tests/i18n-render.test.tsx` renders settings in Chinese and asserts labels, stable test ids and the English fallback. `tests/i18n-prompts.test.ts` asserts the language directive is appended for Chinese, absent for English, and that the doctrine text is unchanged.

## What stays English on purpose

- Model output that is not chat copy: raw provider errors, server validation messages and tool output.
- Identifiers: tool names, tool arguments, model/provider names, thinking-level values, file paths, code and LaTeX.
- Plugin-authored text. The host translates its own chrome around a plugin, not the plugin's content.
- Comments, test names and documentation outside this page's scope.

## If you change an English string

Change it in the component AND in every dictionary that used the old text; the literal is the key, so a rename is a new string. `tests/i18n.test.ts` reports the new literal as missing until it is translated.

## Chinese specifics

The Simplified Chinese dictionary follows one glossary: 会话 (session), 知识图谱 (graph), 提取 (extraction), 提示词 (prompt), 模型 (model), 服务商 (provider), 思考 (thinking), 轮次 (turn). Use 你, full-width punctuation, and keep product nouns, code and math untouched. Terms that the learner must recognize in English (e.g. `prompt`, `token`, model names) keep their English form on first use.
